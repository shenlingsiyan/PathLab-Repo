# 单次嘲讽点 · 制作要点

## 设计决策

- **约束不是机制**：嘲讽点不做方向控制、不发移动事件、不是敌人 AI——它只是
  给寻路加一条「必经集合」约束。设施只提供数据与有效集合计算；
- **有效集合双条件**：`起点可达 t` **且** `访问 t 后能到终点`。只查起点可达会
  把死胡同点误判有效，导致全图无解的假失败。实现：在 `(位置, 进入格)` 状态图上
  从 `(S,S)` 正向可达、从 `(G,*)` 反向可达，点有效 ⇔ 存在状态同时双向可达——
  状态图（而非两次独立 BFS）才能同时处理单向通道的进入方向分裂；
- **无解诚实上报**：有效点无法同路共同访问 → `Found=false` + `Note` +
  `MissedTauntCells`，绝不为凑出解而静默丢点；
- **每次寻路重建**：有效集合依赖当前地图与探针，编辑后立即变化，
  `PlanAll` 每次规划前重跑 `TauntPlan.Build`。

## 对算法的契约（ITauntAware）

- 状态扩展 `(Cell, From, Mask)`，进入格子调 `Taunt.Mark(mask, cell)`；
- 终点条件 `Here == Goal && Taunt.Complete(mask)`；
- **代价口径完全不变**：BFS 仍按步数、Dijkstra 仍按进入代价、07 仍字典序、
  06 仍得分——约束只过滤解，不改目标函数；
- 所有 goal 判定处都要带掩码分量（06 有两处，漏一处 = 有时违反约束）；
- 07 的路径审计在有嘲讽约束时允许重复格（死胡同收集需要回返）。

## 与其他设施的兼容规则

- 特殊移动**落点**在嘲讽点上 → 置位；
- 跳板**连锁中间落点**不是路径节点 → 不置位；
- 传送门落点、单向通道出口均照常置位/判定。

## 接入范围（当前事实）

`00` `01` `06` `07` 已接入；`03` `05` 是复合目标模块，载体在状态栏提示
「该算法不执行嘲讽点约束」，不静默违反。查询模块 `02` `04` 无 S→G 路径，不参与。

## 自检要点

9 组 47 条断言（SelfTest.cs taunt 区段）：普通必经 / 死胡同无效点 /
访问后无法到终点的封死用例 / 多点同路 / 多点无法共同访问（诚实失败）/
与传送、单向、跳板叠加 / 落点置位与中间落点不置位 / 每次重建。
