# 网格寻路算法制作 · 思路精华

八轮实战（00 BFS → 07 字典序 Dijkstra）沉淀出的流程。**顺序不可颠倒**：
口径 → 算法 → 契约 → 验证 → 测试 → 界面 → 文档 → 复核。

## 0 总纲

> 先把「敌人的行为」翻译成一个**有唯一最优定义的目标函数**，
> 再用**能证明最优性**的算法实现它，
> 用**与被测代码不同源**的 oracle 验证它，
> 最后只用**三条 UI 通道**接入。

任何一步做不到，就在结果里**诚实降级**，而不是把近似当成最优、把失败当成功。

## 1 先写口径，不写代码

动手前必须能回答这六句，并且能写成数学式：

| 问题 | 例（07） |
|---|---|
| 优化什么？ | 字典序 `(ReferenceCount, PathLength)` |
| 什么算合法路径？ | 4 邻接、不进墙、不出界、不重复格子、`S → E` |
| 哪些格子特殊？ | 参考点＝软障碍；墙永远不可通行；`S/E` 不计 |
| 平局怎么办？ | 同代价按 `y`、`x` 固定顺序 ⇒ 同图同路径 |
| 输入不合法怎么办？ | 越界／墙当作起点终点 ⇒ `Found=false` + `Note`，**不静默替换** |
| 输出哪些字段？ | `Found/Path/ReferenceCount/Path.Count-1/IsOptimal/Explored/ElapsedMs/TerminationReason` |

规则：**没有口径的算法，最后都会变成一堆 if**。口径先落进 README 的第一节，再落进代码注释。

## 2 选算法：一张判断表

| 目标 / 约束 | 手段 | 是否最优 |
|---|---|---|
| 步数最少 | BFS | 是 |
| 进入代价最小 | Dijkstra（越界当墙，起点不计费） | 是 |
| 两个目标有**绝对优先级** | 二元代价**字典序** Dijkstra | 是 |
| 最大化、且路径不能重复格子 | DFS 枚举简单路径 + 安全上界剪枝 | 预算内跑完才算 |
| 空间指数级、只要个像样结果 | 束搜索 Beam | 否（`IsOptimal=false`） |
| 必须经过某集合中的一格 | 两趟 Dijkstra：前置代价 + 后置代价，取 `emin` | 是 |
| 只问“哪儿最远 / 哪儿合适” | 反向 BFS 距离场，做**查询模块**而不是 `IPathfinder` | 是 |

字典序的成立条件只有两条：**每条边的分量非负**、**字典序对加法保序**。满足即用
`PriorityQueue<Cell, (主分量, 次分量, Y, X)>`，出队比对 `best[]` 丢弃过期记录
（一个格子会多次入队，旧记录不能拿旧代价继续扩展）。

硬禁止清单（都踩过或差点踩）：

- 用加权折中（`0.001 × 穿越 + 步数`）代替绝对优先级；
- 用固定大惩罚系数冒充字典序；
- 把软障碍设成永久障碍（约束一收紧就假失败）；
- 为了“看起来最优”而改写 `IsOptimal`；
- 在不允许重复格子的最大化问题里放开访问限制（可以无限刷分）。

## 3 契约优先，接口与字段按需生长

- 主干只实现 `IPathfinder`；**能力接口只在真需要时新增**：
  `IReferencePointModule`（单点）/ `IViaPointModule`（经过格＋约束区）/ `IReferenceCellSetModule`（集合）。
- 结果字段先复用既有语义：步数 = `Path.Count-1`、扩展 = `Explored.Count`、耗时 = `ElapsedMs`；
  只有语义确实不重叠才新增（`Score` 得分、`ReferenceCount` 穿越数）。
- 用户输入由载体 `Apply...` 推给模块，**模块自己校验**；空集合、`null` 都是合法输入。
- 模块不依赖跨实例全局状态；每个机器人一个独立实例，对比运行互不干扰。
- **地图设施（传送门等）走可选能力接口**：`ITransitionAware { IPathProbe? Probe }`，
  探针把「普通邻接」与「设施连接」分开返回，计价口径留在算法里（`00` 算 1 步、
  `01` 算门费 + 落点地形费、`06` 传送权重 0、`07` 落点按参考点计穿越）。设施只发布连接，
  不排序出口。门格直接设为墙并记住原价，于是「设施格不可停留」对所有算法一次成立，
  也不需要改地图数据结构。搜索克隆地图的模块用 `Probe.For(clone)` 重绑。
- 适配时先问「这个目标函数怎么给一次传送定价」，答不出来就说明该模块不该在首版接入；
  组合型模块（多段腿）最容易踩到「返程复用去程格子」的重复问题，要么先避让、避不开再回退，
  要么明确写清它不是简单路径。

## 4 独立验证：oracle 必须“不同源”

> 用被测代码验证被测代码 = 没验证。

- oracle 只允许共享**地图基础操作**（`Neighbours` / `CostAt` / `IsWall`），
  权重公式、计数口径在自检里**重写一遍**。
- 小图上用**不剪枝的全枚举**（全部简单路径）当 oracle，按目标函数取最优。
- 另写一个 `ValidateXxx(result, map, inputs)`：只走最终路径，重算长度／计数，
  并检查越界、穿墙、相邻（曼哈顿距离 = 1）、重复坐标；**与报告值不一致就报错**。
- 搜索内部也调用同一套 `CheckPath`：重建出的路径不合法 ⇒ `路径重建校验失败`，绝不返回该路径。
- 期望数值**由 oracle 算**，不要手算（07 的 F 用例手算成 4 步，实际最优 3 步，就是靠 oracle 抓出来的）。

## 5 测试矩阵 A–M（固定骨架）

| 槽位 | 语义 |
|---|---|
| A | 退化输入：空集合 / 无标记点，应与基础算法等价 |
| B | 约束存在但不触发：应完全按主目标解 |
| C | 约束挡在最短路线上、有绕行：**更长也必须避开** |
| D | 约束封死无解通路：允许必要穿越 / 唯一门 |
| E | 多点联合阻断：取最小代价，不是“遇到第一个就停” |
| F | 多解同主目标：由次级目标裁决 |
| G | 短路径劣于长路径：验证优先级不倒置 |
| H / I | 起点 / 终点与特殊格重合：固定端点不计 |
| J | 重复输入：去重后只算一次 |
| K | 特殊格与墙重合：**墙优先**，永远不可通行 |
| L | 彻底不可达：`Found=false`、原因固定短语、`IsOptimal=false` |
| M | 起点 = 终点：单格、长度 0、成功 |

再补四条：**输入校验**（越界／墙端点／`null` 图）、**伪造结果**必须被 `ValidateXxx` 抓出、
**N 确定性**（同实例连跑两次同路径同计数）、**与既有模块对照**（同图同长 / 同代价）。

断言分三层：
1. 契约层：`Found`、路径合法、无重复、`Explored` 有记录、`TerminationReason` 在固定表内；
2. 最优层：与 oracle 的数值逐项相等；
3. 集成层：`--selftest` 通用循环、对比运行、机器人步数 = 路径边数。

## 6 诚实性

- `IsOptimal = true` 只在**证明过**之后写；
- `TerminationReason` 是**固定短语表**，README、界面、测试引用同一字面量，不各写一套；
- 预算耗尽 ⇒ 返回“目前最好的合法解”＋`未证明最优`；连一条合法路径都没有 ⇒ 失败；
- 失败一律给 `Note`，绝不伪造路径、绝不把墙当软障碍。

## 7 界面只走三条通道

已有且够用的三条：**参考点行 / 角标（`R`、`F`、空心方框）/ 状态栏**。

- 切换算法时按能力接口决定：显示与否、提示语、默认值（用户点过就不再覆盖）；
- 集合型输入用 toggle 拾取（点一次加入、再点移出），值标签给 `N 个`；
- 新地图清空用户输入；
- 状态栏**按模块类型分支**（得分分支不能把步数模块也吞进去——07 修过一次）；
- 对比行压缩：`N步/C代价`、`N步/S分/精确|未证`、`N步/K穿`；
- 新增一整个控件行之前，先问“能不能复用参考点行”。能就不加。

## 8 文档固定八节

`口径` → `流程`（含伪码）→ `输入 / 输出`（字段表）→ `独立验证` → `测试表` → `界面` → `约束` → `极简`。
每节只写**别人能据此复核**的内容：公式、伪码、字段、字面量、数字。

## 9 踩坑清单（本项目实测）

- `GridMap.SetCost` 拒绝把 `Start/Goal` 涂成墙 ⇒ 测“墙终点”必须**先涂墙、后设 Goal**；
- 一个超长自检方法里，局部函数 / 局部变量重名 → `CS0128`；嵌套类与方法同名 → `CS0102`；
- 优先队列同一节点多次入队 ⇒ 必须做过期记录比对；
- 用 `if / else if` 推送能力接口，会在“一个类实现两个接口”时漏推 ⇒ 用两个独立 `if`；
- 复用 `TerminationReason` 的显示分支，会把新模块显示成“得分 0” ⇒ 先按模块类型分支；
- 用正则批量重命名自检变量，会误伤已有用例 ⇒ 手工改，置信度不够就重跑自检；
- PS 自动化里 `CB_SETCURSEL` / `SendKeys` / 真实鼠标点击都不可靠 ⇒ 用 UIA（Expand + SelectionItem）。

## 10 交付检查清单

1. `algorithms\NN_name\Xxx.cs` + `README.md`（八节）；
2. 能力接口 / 结果字段**只在需要时**新增，并在契约文档里登记；
3. 自检：oracle + A–M + 输入校验 + 伪造结果 + N；
4. `tools\sync-algorithms.ps1` → `dotnet build`（Debug/Release）→ `--selftest` 全绿、0 警告；
5. UI 实测：选中后提示与默认值、拾取增减、状态栏、对比行、运行/暂停；
6. 三份 README 各补一行（根 / `algorithms` / `PathLab`）；
7. 极简复核：有没有多出来的控件行、字段、文件、第三目标（转弯惩罚、地形权重、路径偏好）。

## 11 极简主义（用户长期规则）

- 一个类、一张优先队列、两张字典，就能表达上面全部方法；
- 公开面只放**别人复算需要**的函数（计数、校验、评分），其余全 `private`；
- 不引入缓存层、抽象基类、插件框架、额外动画；
- 文档不写空话：每个数字、每条原因都能在代码或自检里指到出处。
