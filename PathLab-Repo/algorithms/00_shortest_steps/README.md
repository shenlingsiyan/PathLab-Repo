# 00 · 最短路程路径算法（BFS）

## 名称

`00-shortest-steps` — 最短步数广度优先搜索。

## 目标

**只最小化移动步数**，完全忽略格子的进入代价：

- 墙仍然不可通过；
- 代价 1 与代价 9 在搜索中完全等价；
- 返回路径的步数最少，但总代价可能远高于最小代价路径。

## 算法

标准 FIFO 广度优先搜索：

1. 起点入队并标记已访问；
2. 出队一格，按固定邻居顺序（右、左、下、上）把未访问、非墙的邻居入队；
3. **入队时**标记访问，保证每个格子只进入队列一次；
4. 第一次出队终点即得到步数最少的路径，沿 `previous` 回溯。

固定邻居顺序让同图的平局结果可复现，但平局不是全局 `(y, x)` 字典序。

## 与最小代价算法的差别

| | 最短路程 (BFS) | 最小代价 (Dijkstra) |
|---|---|---|
| 优化目标 | 步数 | 进入代价之和 |
| 权重 | 忽略 | 1..9 |
| 数据结构 | FIFO 队列 | 优先队列 |
| 典型行为 | 穿过高代价捷径 | 绕远避开高代价 |
| 代价口径 | 报告实际路径代价，但不优化它 | 报告最优代价 |

在自检地图上两者会给出不同结果：BFS 走 6 步、代价 46；Dijkstra 走 10 步、代价 10。

## 复杂度

- 时间：`O(V + E)`，本网格 `E ≤ 4V`；
- 空间：`O(V)`。

## 输入输出

输入 `GridMap`；输出 `SearchResult`：

| 字段 | 含义 |
|---|---|
| `Found` | 是否可达 |
| `Path` | 步数最少的路径（含首尾） |
| `Cost` | 该路径的实际进入代价之和（非最优） |
| `Explored` | 出队顺序，用于可视化 |

## 适用与不适用

- 适用：只关心到达速度、地形代价可忽略、或作为「步数下界」对照。
- 不适用：不同地形代价差异明显、需要真正省钱时——应使用 `01_min_cost`。

## 传送门（特殊连接）

本模块实现 `ITransitionAware`，可选地读取 `IPathProbe` 提供的额外连接：

```csharp
module.Probe = portalFacility.CreateProbe(map);   // 载体在创建机器人后调用；null = 纯 4 邻接
```

- 普通邻接仍按固定顺序（右、左、下、上），传送连接排在普通邻接**之后**展开；
- 传送在本模块里**恒为 1 步**：地形代价、参考点都不参与，BFS 的边权仍全为 1，
  因此步数最优性不受影响；
- 传送门格在地图里是墙，普通邻接本来也进不去，所以「门格不可通行」不需要额外判断；
- `Probe = null` 时行为与本文件前面的描述**逐字节相同**（自检用例 `portal A` 对照过）。
