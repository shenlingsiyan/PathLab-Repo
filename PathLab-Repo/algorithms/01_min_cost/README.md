# 01 · 最小代价路径算法（Dijkstra）

## 名称

`01-min-cost` — 最小进入代价的加权 Dijkstra。

## 目标

**只最小化进入代价之和**，不优化步数：

- 每次移动付 `map.CostAt(目标格)`；
- 墙（0）不可进入，空地 1..9；
- 起点不计费，终点计费；
- 总代价最优，但步数可能比最短路程路径更多。

## 算法

标准优先队列 Dijkstra：

1. 起点距离 0，入队，优先级 `(0, y, x)`；
2. 每次取出累计代价最小的格子；
3. 对每个非墙邻居松弛：`新代价 = 当前代价 + 进入代价`；
4. 首次出队终点即为最优；沿 `previous` 回溯。

平局用 `(累计代价, y, x)` 决定，因此同图同结果可复现。

## 与最短路程算法的差别

| | 最短路程 (BFS) | 最小代价 (Dijkstra) |
|---|---|---|
| 优化目标 | 步数 | 进入代价之和 |
| 权重 | 忽略 | 1..9 |
| 数据结构 | FIFO 队列 | 优先队列 |
| 典型行为 | 穿过高代价捷径 | 绕远避开高代价 |
| 在自检地图上 | 6 步 / 代价 46 | 10 步 / 代价 10 |

## 为什么不是 A*

本模块刻意不带启发式：

- 它给出的是**真实最优代价基准**，后续 A*、Greedy、JPS 都以它为对照；
- 启发式会引入可采纳性、平局、权重缩放等额外变量，不适合作为第一层基准。

## 复杂度

- 时间：`O((V + E) log V)`；
- 空间：`O(V)`。

## 输入输出

输入 `GridMap`；输出 `SearchResult`：

| 字段 | 含义 |
|---|---|
| `Found` | 是否可达 |
| `Cost` | 最优进入代价之和（不含起点） |
| `Path` | 代价最优路径（含首尾） |
| `Explored` | 出队顺序，用于可视化 |

## 适用与不适用

- 适用：地形代价差异明显、需要真正省钱、作为最优性基准。
- 不适用：只关心步数且代价全为 1 时，BFS 更简单更快。

## 传送门（特殊连接）

本模块实现 `ITransitionAware`，可选地读取 `IPathProbe` 的额外连接：

```csharp
module.Probe = portalFacility.CreateProbe(map);   // 载体在创建机器人后调用；null = 纯 4 邻接
```

传送边的代价口径（本模块自己决定，设施不参与）：

```text
传送边(u → ExitCell) = TeleportCost + CostAt(ExitCell)
                        ↑ 门费（只收一次）  ↑ 落地即计费，与普通移动一致
```

- 这条口径正好对上 `C_entry + C_portal + C_exit`：`C_entry` 是走到入口格的普通移动
  （进入入口格时已付），`C_exit` 是落在出口格上的地形代价；
- 门费为 0、出口格便宜时，Dijkstra 会主动传送；门费高或出口在昂贵地形上时，
  传送边权变大，算法自然回到普通路线（自检用例 `portal E` / `portal F` / `portal J`）；
- 边权恒 `≥ 1`（出口格可通行 ⇒ `CostAt ≥ 1`），Dijkstra 的最优性前提不变；
- `Probe = null` 时行为与本文件前面的描述完全相同（自检用例 `portal A` 对照过）。
