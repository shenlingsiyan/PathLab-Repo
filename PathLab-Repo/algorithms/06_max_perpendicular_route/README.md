# 06 · 最大垂直距离路径

特殊敌人的**得分最大化路线**：给定标记点 `Q`，找一条从出怪口 `S` 到入怪口 `E`
的**简单路径**（4 邻接、不进墙、不出界、**同一条路径不重复经过格子**），
使路径上每条连续线段「长度 × 该线段所在直线到 `Q` 的垂直距离」之和最大。

它**不是**最短路径模块：步数、进入代价都不是目标，得分才是；得分高的路线通常更长。

| 项 | 值 |
|---|---|
| Id | `06-max-perpendicular-route` |
| 类型 | 路径模块 `IPathfinder` + `IReferencePointModule` |
| 实现 | `MaxPerpendicularPathfinder` |
| 目标 | `Score`（加权得分，越大越好），`Optimal = false`（见下） |
| 依赖 | 仅用 `00_shortest_steps` 取一条合法的种子路线；不依赖 01/02/03/04/05 |
| 复杂度 | 精确：简单路径空间指数级（受预算截断）；近似：`O(BeamWidth · V · E)` |
| 结果字段 | `Score` / `IsOptimal` / `TerminationReason`（`SearchResult` 专为得分模块新增） |

`Optimal = false` 是因为本模块对外承诺的是「预算内尽力而为」：只有搜索**跑完**时才在
单次结果里把 `IsOptimal` 置 `true`，界面与自检都读这个字段，不看模块级声明。

## 口径

### 1. 标记点 `Q`

```csharp
module.ReferencePoint = new Cell(5, 5);   // 越界 → 失败；null → 回退到 map.Goal
```

- `Q` 可以是空地，**也可以是障碍**：本模块只做算术，不要求 `Q` 可达；
- `Q` 只影响权重，不参与连通性判断，也不改变地图；
- 越界一律失败（`Note = 标记点超出地图边界`），不静默替换成入怪口。

### 2. 目标函数

按连续方向把路径切成最大线段 `i = 1..n`，`li` 为线段长度（边数），`di` 为该线段所在
**无限延伸直线**到 `Q` 的垂直距离：

```text
F(P) = Σ li * di
```

注意是到**无限延伸直线**的距离，不是到有限线段的最近距离。

### 3. 逐边转换（实现口径）

四方向单位网格上，每条线段的所有边落在同一条直线，权重对每条边都相同，于是

```text
水平移动 (x, y) → (x ± 1, y)：w(e) = |y - qy|    // 该行到 Q 所在行的距离
垂直移动 (x, y) → (x, y ± 1)：w(e) = |x - qx|    // 该列到 Q 所在列的距离
F(P) = Σ(e ∈ P) w(e)
```

例：`Q = (5, 5)`，`y = 2` 上连续向右 4 格 → `|2-5| = 3`，合计 `4 × 3 = 12`；
`x = 9` 上连续向下 3 格 → `|9-5| = 4`，合计 `3 × 4 = 12`。
实现**不做线段合并**，搜索过程中逐边累加；合并只是定义上的等价说明。

### 4. 为什么必须禁止重复格子

边权一律非负（`|y - qy| ≥ 0`），若允许重复，任意正权重环都能无限叠加得分，
目标函数没有上界。因此路径合法性包含「简单路径」这一条，搜索用 `visited` 位图强制。

## 流程

1. 校验：空图、标记点越界、`S/E` 越界或为墙 → 失败并给 `Note`；
2. 用 `00_shortest_steps` 求一条种子路线：它一定是合法的简单路径，
   保证预算耗尽时也有真实路线可返回，而不是凭空造一条；
   `00` 也失败 → `TerminationReason = 不存在合法路径`（此时没有可返回的路线）；
3. `S == E`：唯一的简单路径就是单格 `[S]`，得分 0，直接判最优；
4. 否则按 `Mode` 跑精确搜索或束搜索，全程以种子路线为初始最好解；
5. 结束后统一回填 `Score` / `IsOptimal` / `TerminationReason`，`Cost` 始终是
   该路径的实际进入代价之和（与 00/01 同一口径，方便界面复用）。

### 精确搜索（`ScoreSearchMode.Exact`，默认）

```text
Walk(current, score):
    到达 E        → 与最好解比较（得分更高，或同分时步数更少），记录后回溯
    扩展节点 + 1  → 超预算 / 超时则中止并保留当前最好解
    安全上界剪枝  → score + 最大单步权重 * 剩余未访问可通行格数 < 最好得分 ⇒ 剪掉
    对四个邻格    → 跳过越界 / 墙 / 已访问，按「权重降序、y、x」排序后逐个深入
```

- 剪枝是**安全**的：剩余每步权重不超过 `最大单步权重`，简单路径最多再用
  「未访问可通行格数」个格子，因此剪掉的子树不可能出现更高得分；
- 排序只影响找到好解的速度与剪枝效果，不改变最优解；
- 搜索跑完 = 已枚举所有简单路径 = `IsOptimal = true`，`TerminationReason = 找到精确最优路径`。

不使用 Dijkstra / A* / 取负权最短路 / BFS 冒充最优：本问题是最大化简单路径权重，
这些算法既不能保证最优，也无法处理「不能重复格子」这一约束。

### 束搜索（`ScoreSearchMode.Beam`）

逐层维护若干**部分路径**（各自带 `Path` / `Head` / `Score` / 自己的 `visited` 位图）：

- 每层扩展全部候选的四个邻格（跳过墙与自身已访问），到 `E` 的直接比较最好解；
- 按「得分降序、步数升序、y、x」排序，保留前 `BeamWidth` 个作为下一层；
- 任一时刻超预算即中止。

束搜索会丢弃低分部分路径，**可能丢掉全局最优解**，所以其结果
`IsOptimal = false`，`TerminationReason = 近似搜索 · 束宽 N（未证明最优）`。

### 预算与结束原因

| 属性 | 默认 | 作用 |
|---|---|---|
| `MaxExpandedNodes` | `150000` | 扩展节点上限 |
| `MaxMilliseconds` | `300` | 墙钟上限，每 256 次扩展检查一次 |
| `Mode` | `Exact` | `Exact` / `Beam` |
| `BeamWidth` | `64` | 束搜索每层保留的部分路径数 |

| `TerminationReason` | `IsOptimal` | 含义 |
|---|---|---|
| `找到精确最优路径` | `true` | 精确搜索跑完（或 `S == E`） |
| `近似搜索 · 束宽 N（未证明最优）` | `false` | 束搜索正常结束 |
| `搜索超时（未证明最优）` | `false` | 精确搜索到达时间上限 |
| `达到搜索节点上限（未证明最优）` | `false` | 精确搜索到达节点上限 |
| `搜索超时（未证明最优）· 近似搜索` 等 | `false` | 束搜索触发预算 |
| `不存在合法路径` | `false` | 无路线（`Found = false`，`Note` 同文） |

预算耗尽时返回的是**目前找到的最好合法路线**（至少是种子路线），不会被当作最优；
连一条完整路线都没有时返回失败，不会伪造路径。

## 输入 / 输出

```csharp
var module = new MaxPerpendicularPathfinder
{
    MaxExpandedNodes = 3_000_000,   // 小图可放开
    MaxMilliseconds = 5_000
};
module.ReferencePoint = new Cell(2, 2);      // 标记点 Q
SearchResult result = module.Search(map);

result.Found              // 是否有可返回的合法路线
result.Path               // S → … → E（简单路径，不重复格子）
result.Score              // 加权得分（= CalculatePathScore(Path, Q)）
result.Cost               // 该路径的实际进入代价之和（不是目标函数）
result.IsOptimal          // 是否已证明全局最高分
result.TerminationReason  // 见上表
result.Explored           // 搜索访问顺序，供画面点阵
result.ElapsedMs          // 搜索耗时（载体还会用整体计时覆盖）

module.UsedReference      // 上次实际使用的标记点（失败时也可能已回填）
module.FarthestPoint      // 恒为 null：本模块没有转折点角标，路径画实线
```

指标体系（模块自带两个静态函数，界面与报告共用，避免各处自己算一遍）：

```csharp
int turns = MaxPerpendicularPathfinder.TurnCount(result.Path);          // 相邻两步方向变化次数
double average = MaxPerpendicularPathfinder.AverageEdgeWeight(          // 步数为 0 时返回 0
    (long)result.Score, result.Path.Count - 1);
```

`TotalScore` 与 `AverageEdgeWeight` 一起看：总得分升高可能来自「路更长」，
平均单步权重升高才说明路线**整体**离 `Q` 更远。

## 独立验证

```csharp
public static long MaxPerpendicularPathfinder.CalculatePathScore(
    IReadOnlyList<Cell> path, Cell marker)
```

只遍历 `path` 的相邻坐标、按水平/垂直规则累加 `|y - qy|` 或 `|x - qx|`，
**不读取搜索过程中的任何累加器**；`path.Count < 2` 时返回 0。
自检把它与搜索报告的 `Score` 逐项对照，另外用一个**独立递归 oracle**
（不带剪枝、直接枚举全部简单路径取最大）在小图上核对最优值。

## 测试（`--selftest`）

| 用例 | 构造 | 断言 |
|---|---|---|
| 规格算式 | `Q=(5,5)`，`y=2` 四步 / `x=9` 三步 | 均得 12，与逐边累加一致 |
| A 标记点居中 | 5×4，`S=(0,1)` `E=(4,1)`，`Q=(2,1)` | 得分 24 = oracle；精确最优；优于最短路（0）；经过 `y=0` 或 `y=3` |
| B 标记点在边缘 | 5×4，`S=(0,0)` `E=(4,0)`，`Q=(0,0)` | 得分 40 = oracle；`Score>0` 且步数 > 4（远侧额外收益） |
| C 标记点在起/终点 | 3×3，`Q` 分别取 `S` 与 `E` | 两次都与 oracle 一致 |
| D 无障碍 | 4×4，`S=(0,0)` `E=(3,3)`，`Q=(1,1)` | 得分 17 = oracle |
| E 自然障碍 | 5×5，两列 3 格墙夹住 `Q=(2,2)` | 得分 24 = oracle；仍能走到 `y=0/4` 远行 |
| F 狭窄通道 | 2×6 单列走廊（另一列是墙），`Q=(0,0)` | 唯一路线 5 步 / 得分 5；`IsOptimal` |
| G 多候选路线 | 7×3，整行 `y=2` 是墙，`Q=(3,1)` | oracle 16；步数 12 > 最短路 6；最短路得分 0 |
| H 禁止重复 | 同 G | 路径无重复格；得分只来自最终路径（不存在靠绕圈刷分） |
| I 起点=终点 | 3×3，`S=E=(1,1)` | 路径 1 格、步数 0、得分 0、`IsOptimal` |
| J 无合法路径 | 5×5，整列 `x=2` 是墙 | `!Found`；`Note` 与 `TerminationReason` 均为「不存在合法路径」 |
| K 节点上限 | G 图，`MaxExpandedNodes=60` | 仍返回合法路线；`!IsOptimal`；原因含「节点上限」；得分 ≥ 种子 |
| L 束搜索 | G 图，`Mode=Beam`，`BeamWidth=16` | 仍合法；`!IsOptimal`；原因含「近似」；得分 ≥ 种子 |
| M 标记点/闸门校验 | 越界 Q；Q 缺省；Q 是墙；`E` 是墙 | 越界失败、缺省回退 `map.Goal`、墙 Q 照常成功、墙 `E` 报「不可通行」 |
| N 复现与实例隔离 | 同实例连跑两次；两实例各带不同 Q | 同图同分同路径；两个 Q 得到不同得分 |

oracle 口径：从 `S` 递归枚举全部简单路径（不剪枝），只在到达 `E` 时比较得分。
它和模块共享的只有 `GridMap.Neighbours`，权重公式在自检里独立重写，避免“用被测代码验证被测代码”。

## 界面

- 选中本算法后出现 `参考点` 一行，提示改为
  `点格子设标记点 Q(空地或障碍) · 得分 = Σ 步数 × 该步所在直线到 Q 的垂直距离`；
- `R` 角标 = 标记点 `Q`；路径无转折点，所以整条实线；
- 状态栏：
  `最大垂直距离路径 · 46 步 · 得分 205 · 平均 4.5 · 拐弯 23 · 达到搜索节点上限（未证明最优） · 标记点 Q (6, 0) · 扩展 150001 · 52.4 ms`；
- 对比运行只压缩成 `46步/205分/未证`（精确时显示 `精确`），避免挤占两家算法的位置；
- 清空/重画标记点会立即重算；把 `Q` 涂成墙不影响搜索。

## 约束

- 不修改地图、不修改障碍与代价定义：只读 `CostAt`；
- 不改变其它模块：`00` 只被用作种子，调用它不改变它的行为；
- 目标函数只用逐边累加实现，不引入线段合并逻辑（合并会带来额外误差与维护面）；
- 近似结果绝不标注为最优；预算不足时宁可报「未证明最优」也不篡改 `IsOptimal`；
- 平局规则固定为「同分取步数更少，再按 `y`、`x`」，同一张图必须复现同一路线；
- 模块无跨实例共享状态：搜索用的 `visited` / 路径 / 计数器都在实例内，对比运行互不干扰。

## 视觉与实现保持极简

本模块只做一件事：在预算内最大化一个加权得分。类里只有搜索状态机、两个公开静态权重/评分
函数与四个可调参数，不引入图形、动画、缓存或额外的抽象层；界面上只复用已有的
「参考点 + 角标 + 状态栏」三条通道，不新增控件行。

## 传送门（特殊连接）

本模块实现 `ITransitionAware`：

```csharp
module.Probe = probe;   // null = 纯 4 邻接
```

- 传送是**一步、权重 0**：传送没有方向，不产生「到 Q 所在直线的垂直距离」，
  `EdgeWeight` 对非 4 邻接的移动返回 0，`CalculatePathScore` 因此与搜索口径一致；
- DFS 与束搜索都把传送当普通候选展开（排在普通邻接之后），访问位图照常防重复；
- 种子路线（00）也带同一个探针，所以被门围住的起点仍有合法种子；
- 安全上界剪枝仍然成立：剩余每步权重 ≤ `_maxWeight`，传送权重 0 只会更松；
- `Probe = null` 时行为与本文件前面的描述一致（自检 `portal 06` 对照）。
