# PathLab · 寻路可视化载体 + 机器人

独立于 `RMG V1_1 SYSTEM` 的 Windows 桌面程序。它只做三件事：

1. 显示网格、障碍、代价、已探索区域、一个或多个算法的路径与机器人；
2. 允许用户直接编辑地图（放/拆障碍、改空地代价、随时换随机图）；
3. 通过反射加载并调用 `Algorithms/` 下的各个寻路模块。

寻路算法本身不在本目录维护。源目录是 `../algorithms/`，每个算法一个文件夹，
由 `../tools/sync-algorithms.ps1` 拷贝到 `Algorithms/` 后编译。

## 构建与运行

```powershell
# 1. 把算法源拷进载体
powershell -ExecutionPolicy Bypass -File ..\tools\sync-algorithms.ps1

# 2. 编译（Windows，.NET 10 SDK）
dotnet build .\PathLab.csproj -c Release

# 3. 无窗口自检
.\bin\Release\net10.0-windows\PathLab.exe --selftest

# 4. 打开可视化
.\bin\Release\net10.0-windows\PathLab.exe
```

GUI 模式在独占控制台时（从资源管理器启动）自动隐藏控制台窗口；从终端启动则保留终端，
`--selftest` 始终在控制台输出。

## 界面与操作

| 操作 | 效果 |
|---|---|
| `新地图` | 立即生成一张 16×16 随机图；默认优先调用 RMG v3，失败则回退内置生成器 |
| `RMG 生成` | 勾选时新地图优先使用 `RMG V1_1 SYSTEM`；取消则只用内置生成器 |
| `对比运行` | 显示第二行 `蓝 A` / `橙 B` 两栏，选择要对比的两个算法；蓝/橙分别表示路径与机器人；顶部 `算法` 下拉框隐藏 |
| `算法` | 单选模式下切换算法；同图重算，机器人回到起点 |
| `参考点` 行 | 仅当选中的算法需要参考点时出现（`距参考点最远周旋算法`、`障碍群周边最短路径`、`最大垂直距离路径`、`最少参考点穿越最短路径`）；显示当前参考点 / 标记点坐标，或参考点集合的 `N 个` |
| `选参考点` | 进入拾取状态，再左键点格子即设为参考点。周旋算法空地/障碍都可以，障碍群算法只接受障碍，最大垂直距离算法把该格当作标记点 `Q`；最少参考点穿越算法可**连续点多个格子**（再点同一格移出） |
| `半径候选` | 勾选后出现 `目标候选` 一行：`比例` + `半径` 区间（两值留空即取 `R`）+ `L` / `区间` / 候选数量；命中格以空心方框标出 |
| `运行 / 暂停` | 每个机器人沿各自路径逐格移动 |
| `单步` | 全部机器人同时推进一步 |
| `重置` | 全部机器人回到起点 |
| `速度` | 播放间隔（右侧更快） |
| `障碍` | 左键拖动放墙，右键拖动拆墙 |
| `代价` | 左键按 `代价值` 涂格子，右键恢复为 1 |
| `擦除` | 左键拖动把格子恢复为 1（拆墙/清代价） |
| `传送门` | 左键放一个传送门、右键移除；门格立即变成不可通行格，`P` 角标标出 |
| `传送代价` | 0..9，所有门共用一个门费；0 即免费传送 |
| `单向` | 左键放一个单向通道、右键移除；格子照常可走，禁两条逆向边且穿越必须直线，橙色箭头标出 |
| `箭头` | 单向通道的指向（↑ ↓ ← →），放置时生效 |
| `跳板` | 左键放一个指向跳板、右键移除；格子照常可走，绿色箭头 + 距离数字标出 |
| `方向` / `距离` | 指向跳板的固定指向（↑ ↓ ← →）与正整数转移距离（1..15），放置时生效 |
| `嘲讽点` | 左键放一个单次嘲讽点、右键移除；格子照常可走，红色小正方形标出 |
| `应用空地代价` | 把所有非墙格子统一设为 `代价值` |
| `代价值` | 1..9；格子右下角数字即该格进入代价 |

墙 = 代价 0；起点 `S`、终点 `E` 永不可被墙覆盖。编辑地图或切换算法后会立即重算，
但不会自动开始播放。

**同一时刻只有一个工具生效**：`障碍` / `代价` / `擦除` / `传送门` / `单向` / `跳板` / `嘲讽点` / `选参考点` 互斥。
进入 `选参考点` 后绘制按钮全部熄灭，画布左右键都只做拾取（右键不会再放门）；
点任一绘制按钮会立刻取消拾取。角标形状区分类别：`R`（参考点）与 `F`（转折格）是**圆形**，
`P`（传送门）是**方形**，单向通道是**橙色箭头**，指向跳板是**绿色箭头 + 距离数字**，
嘲讽点是**红色小正方形**。

## 两种目标的对比演示

以启动图（RMG，seed 20261025，全图代价 1）为例：

1. 默认 `最短路程 (BFS)`：状态栏约 `26 步 · 代价 26`；
2. 选择 `代价`，把代价值调到 9，在 BFS 路径上涂一格；
3. BFS 不避让：仍是 `26 步`，代价升到 `34`；
4. 切换 `最小代价 (Dijkstra)`：变成 `28 步 · 代价 28`，路径绕开那一格。

同一张图、同一组起终点，只改变目标函数，即可看到「步数最少」与「代价最小」的取舍。

## 对比运行（合并）

勾选 `对比运行` 后，工具栏下方出现对比选择行：`蓝 A` 与 `橙 B` 两个下拉框
用来指定参与对比的两个算法（默认前两个）。载体只为它们各创建一个独立机器人，
在同一张图上同时规划、同时播放：

- A 固定蓝色、B 固定橙色，只运行这两个算法；
- 两栏选了同一个算法时，另一栏自动换回上一次的选择，保证 A 与 B 不同；
- 路径重叠时，上层路径以细芯形式嵌在下层路径内，仍可分辨两条路线；
- 两个机器人同格时并排显示；
- `运行 / 单步 / 重置` 对两个机器人同时生效；先完成的机器人停下，另一个继续走完；
- 对比模式隐藏已探索点，避免两层点阵盖住路径；
- 状态栏格式：`对比运行 · 蓝 最短路程 (BFS) 26步/34代价 · 橙 最小代价 (Dijkstra) 28步/28代价 · 已走 7/7`。

延续上一节的操作：A 选 `最小代价 (Dijkstra)`、B 选 `最短路程 (BFS)` 后再勾选对比，
BFS 走高价捷径（26 步 / 34 代价），Dijkstra 绕行（28 步 / 28 代价），
两条路径、两个机器人会同时出现在同一张图上，差异一眼可见。
取消 `对比运行` 后对比行隐藏，顶部 `算法` 下拉框恢复单选。

每个机器人持有**独立的算法实例**（`AlgorithmHost.Create`），
因此后续的增量重规划算法（如 D* Lite）可以为单个机器人保留状态，互不干扰。

## 距参考点最远周旋算法

选择一个需要参考点的算法（`距参考点最远周旋算法`）后，工具栏下方才出现 `参考点` 一行：
`选参考点` 按钮 + 当前坐标。默认参考点是入怪口 `map.Goal`（`障碍群周边最短路径` 则默认
取行优先第一个墙格）；新地图生成时复位，切换算法时按新算法的要求重新取默认值。

路线由三个已接入模块串联而成，机器人仍用同一套播放机制走完：

1. **选点**：从参考点反向 BFS，取步数最大的可达格（`02_farthest_cell`）；
2. **去程**：出怪口 `S` → 最远格，最小累计进入代价（`01_min_cost`，Dijkstra）；
3. **停滞**：描述里计划停滞指定时间，本可视化程序不做停滞；
4. **返程**：最远格 → 入怪口 `E`，最少移动步数（`00_shortest_steps`，BFS）。

画面标记：

- `R` = 当前参考点（角标），`F` = 本轮最远格（角标、去返程转折点）；
- **实线** = 去程（最小代价），**虚线** = 返程（最短路程）；
- 状态栏：`距参考点最远周旋算法 · 38 步 · 代价 38 · 参考 (6, 0) · 最远 (15, 15) · 扩展 215 …`
  （seed 20261025，RMG 图）。

边界行为：参考点可选空地或障碍。障碍参考点不会回退成入怪口，而是由 02 从其可通行邻格
起步（距离从 1 算）；只有越界参考点、或四周全为墙的参考点才让模块返回失败，
状态栏显示 `不可达（原因）`。对比运行里若 A/B 之一是该算法，两个算法共用同一个参考点。

## 半径候选目标点（预览）

勾选工具栏 `半径候选` 后出现 `目标候选` 一行，只为观察 `04_radius_candidates` 的查询结果，
不创建机器人、不影响正在播放的算法：

- `比例`：`alpha`，默认 `0.5`；非负有限数值，输入非法时显示 `比例无效`；
- `半径`：两个整数输入框（下界 – 上界），闭区间；两端相同是圆周，不同是圆环；
  留空即取基准 `R`，因此默认就是上一版的圆周预览；下界大于上界、或输入非整数时显示对应提示；
- 结果标签：`L=… · R=… · 区间 a–b · 候选 n`，`L` 是出怪口到入怪口的最短**步数**（忽略地形代价），
  `R = floor(L * alpha)`（`R = 0` 也不修正为 1），区间只限制空间距离；
- 画面：落在区间内、可通行且可达的格子画成**空心方框**；
- 候选为 0 属于正常结果（成功但空集），不算失败；只有越界、不可达、参数非法才显示 `失败（原因）`；
- 地图编辑、新地图、改比例或改区间都会自动重算。

## 障碍群周边最短路径

在下拉框选择 `障碍群周边最短路径` 后，`参考点` 一行出现，提示改为
`点障碍设参考点(自动取整块障碍群) · 空心方框为周边格 · F 为本轮经过格`：

- 参考点**必须是障碍**；默认取行优先第一个墙格，没有墙时退回入怪口（随后搜索报 `参考点不是障碍`）；
- 点任意一块障碍，就会自动取它所在的整块 4 邻接连通障碍群，不需要逐格确认；
- 空心方框 = 该障碍群的**周边格**（贴墙但可通行的格子）；`F` = 本轮真正经过的那一格；
- 路线必须至少经过一个周边格，并在此前提下取总代价最小；两趟 Dijkstra 选点，不额外加价；
- 状态栏：`障碍群周边最短路径 · 16 步 · 代价 16 · 参考 (0, 5) · 经过 (0, 4) · 周边 3 格 …`；
- 失败时状态栏给原因：`参考点不是障碍`、`障碍群周围没有可通行格子`、
  `周边格子无法同时连接出怪口与入怪口`，并且不会退化成无障碍最优路线；
- 把参考点涂成空地后立即重算并报 `参考点不是障碍`；点另一块障碍群即换群重算。

## 最大垂直距离路径

在下拉框选择 `最大垂直距离路径` 后，`参考点` 一行出现，提示改为
`点格子设标记点 Q(空地或障碍) · 得分 = Σ 步数 × 该步所在直线到 Q 的垂直距离`：

- 这一行的格子是**标记点 `Q`**，不是起点/终点，也不要求可达；默认 `Q = 入怪口`；
- 目标不是最短也不是最便宜，而是让路线尽量沿「远离 `Q` 的水平/垂直线」走：
  水平移动记 `|y - qy|`、垂直移动记 `|x - qx|`，路径总得分是逐边累加；
- 路径必须是**简单路径**（不重复格子），否则可以绕圈无限刷分；
- `R` 角标 = 标记点 `Q`；没有转折点，整条路径画实线；
- 状态栏：
  `最大垂直距离路径 · 46 步 · 得分 205 · 平均 4.5 · 拐弯 23 · 达到搜索节点上限（未证明最优） · 标记点 Q (6, 0) · 扩展 150001 · 52.4 ms`；
- 平均单步权重 = 总得分 / 步数（步数 0 时为 0）：总得分升高可能来自路更长，
  平均权重升高才说明路线整体更远离 `Q`；
- 结束原因会明确写出是否已证明最优：`找到精确最优路径` / `近似搜索 · 束宽 N（未证明最优）` /
  `搜索超时（未证明最优）` / `达到搜索节点上限（未证明最优）` / `不存在合法路径`；
- 16×16 地图的简单路径空间是指数级，默认预算（15 万节点 / 300 ms）跑不完精确搜索，
  因此实际显示「达到搜索节点上限（未证明最优）」；小图（自检里的 3×3～5×5）能真正枚举完并报精确最优；
- 对比运行里压缩为 `46步/205分/未证`（精确时显示 `精确`）。

预算与模式（`MaxExpandedNodes` / `MaxMilliseconds` / `Mode` / `BeamWidth`）是模块属性，
默认值写死为「界面不卡顿」，暂不放控件；需要调参时改 `MaxPerpendicularPathfinder` 的默认值或
在代码里构造实例。设计细节见 `../algorithms/06_max_perpendicular_route/README.md`。

## 最少参考点穿越最短路径

在下拉框选择 `最少参考点穿越最短路径` 后，`参考点` 一行出现，提示改为
`点格子加入参考点(再点移出) · 参考点为软障碍：先少穿越、再最短`：

- 参考点是**集合**：点一格格子加入，再点同一格移出，可连续点；值标签显示 `N 个`；
- 目标是严格的字典序：**先让穿越次数最少，再让步数最短**；两次穿越/5 步也永远输给零穿越/30 步；
- 参考点不是墙：封死所有无穿越通路时，允许穿过必要的参考点，且穿越数量必须最少；
- 普通障碍永远不可通行；参考点即使画在墙上也走不进去；
- 起点 `S` 与终点 `E` 固定，**即使它们是参考点也不计入穿越次数**；
- 每个参考点画一个 `R` 角标，路径画实线；
- 状态栏：
  `最少参考点穿越最短路径 · 26 步 · 穿越 0 · 找到最少穿越的最短路径 · 参考点 3 个 · 穿越 0 · 扩展 78 · 0.4 ms`；
- 对比运行压缩为 `26步/0穿`；
- 换图会清空集合；新选中本算法时集合为空（等价于普通步数最短路），
  点过格子后才按「软障碍」重算。

设计细节见 `../algorithms/07_min_reference_traversal/README.md`。

## 混乱传送门（地图设施）

`传送门` 模式放置的是**地图拓扑设施**，不是算法：门与门之间是**全对多**连接，
任意一个门都能当另一个门的出口，由寻路算法自己决定走哪个出口。

- 门格**永远不可通行**：放置时该格变成墙（原价记下，移除时还原），任何算法都不能踩上去停留；
- 传送抽象为 `EntryCell → 门 A → 门 B → ExitCell`，入口与出口都必须是门四周的普通可通行格；
- 门费统一（`传送代价` 数字框），`00` 把传送算 **1 步**，`01` 算 **门费 + 落点地形费**；
  出口由算法按自己的目标挑，设施不做任何排序；
- `P` 角标 = 传送门；路径遇到传送会断开（不画假斜线）；状态栏追加 `· 传送 N 次`；
- 六个路径模块都接入了探针：`00` 算 1 步、`01` 算门费+落点地形、`03` 两段腿都能跳、
  `05` 两趟 Dijkstra 都能跳、`06` 传送权重 0（只是多一步）、`07` 穿越数按落点计；
- 换新地图会清空所有门。

完整规则、接口与测试见 `PORTALS.md`。

## 单向通道（地图设施）

`单向` 模式放置的是**地图规则设施**：通道格照常可通行（不涂改地图），
禁止「从首部侧进入」与「向尾部侧离开」两条边，并且**穿越必须直线**——
步行进入通道后唯一出口是直行对侧（尾进首出、侧进对侧出），通道内不允许
拐弯；传送落点没有几何进入方向，保留除尾侧外的全部出口。

- 规则在探针层统一生效（`OneWayFacility.ApplyTo` 过滤普通邻接并按进入方向
  收紧出口 `ExitsAfter`），**所有接入探针的算法自动遵守**，没有任何算法内部
  出现单向通道判断；BFS / Dijkstra 类模块在通道格上按「(格子, 进入格)」分裂
  状态，其余格子退化为单状态；
- 传送跳不受箭头约束（不是几何边），落点之后的步行照常受限，
  步行进入通道后不再提供传送（必须直行走完）；
- 边界/障碍照常生效：缺失的首尾边只删边、不删设施；
- `单向` 与传送门共用工具互斥；橙色箭头指向首部；
- 换新地图会清空所有通道。

完整规则、与任务书 4.3 节的差异说明及测试见 `ONEWAY.md`。

## 指向跳板（地图设施）

`跳板` 模式放置的是**可选移动设施**：格子照常可走，单位可以普通穿越；站在跳板格
或它的四邻格上时，还会额外获得一条「沿固定方向、按可修改距离直接转移」的候选边。

- 跳板格**不涂改地图**，普通 4 邻接全部保留，不触发转移也能正常进出；
- 一次转移直接落在 `Position + Direction × TransferDistance`，**中途的墙不检查**；
- 落点若正好是另一个启用跳板，**强制继续连锁**，不允许中途停留或退出；
- 最终落点越界/是墙 → 整条不可用；连锁重复触发同一跳板 → 判循环、整条不可用；
  以上失败都不影响普通穿越；
- 禁用跳板按普通格处理：空地可作终点，墙则让连锁失败；
- 设施只发布“普通邻接 + 跳板块”两类候选，代价字段为 0：几何距离不折算成代价，
  由各算法按自己的口径定价（BFS 记 1 步，Dijkstra 记落点地形费）；
- `SearchResult.LauncherJumps` 保留触发 ID 与每次落点，`LauncherPathPlan` 负责回放；
- 设施无缓存，改方向/距离、启禁用、改落点通行性都会在下一次查询立刻生效；
- 绿色箭头 + 距离数字 = 指向跳板，橙色仍是单向通道；状态栏追加 `· 跳板 N 次`；
- 换新地图会清空所有跳板。

完整规则、接口、运行时事件与 12 组测试见 `LAUNCHERS.md`。

## 单次嘲讽点（地图设施）

`嘲讽点` 模式放置的是**路径约束设施**：格子照常可走，但它向寻路系统提出
「必须经过」的要求。每次寻路前先计算有效集合 `T'`（每个点单独都能出现在某条
合法 S→G 路线中），然后把搜索状态扩展为 `(位置, 进入格, 已访问位掩码)`：

- 只有 `位置 == 终点 且 掩码 == 全部有效点` 才算找到路径；
- 每个有效点只需访问一次；重复经过不会重复计数；
- 多个有效点必须由**同一条**合法路线全部访问；无法共同访问时返回无合法路径
  并给出原因，不会丢掉任何一个点；
- 被墙封死、不可达、或访问后无法抵达终点的点不参与约束；
- 有效集合与搜索都使用统一探针，因此单向通道、传送门、指向跳板的移动规则
  全部纳入可达性判断，特殊移动落点是嘲讽点时正常置位；
- `00` / `01` / `06` / `07` 已接入；`03` / `05` 是复合目标模块，不执行该约束，
  选中时状态栏会明确提示；
- 状态栏追加 `· 嘲讽点 x/y`；无缓存，任何设施或地形变化都在下一次规划时重建；
- 换新地图会清空所有嘲讽点。

完整规则、接口与测试见 `TAUNTS.md`。

## 机器人

`Robot` 不关心具体算法：

```csharp
robot.SetMap(map);          // 换图（不自动规划）
robot.SetAlgorithm(alg);    // 换算法（不自动规划）
robot.Plan();               // 调用算法，记录 Result
robot.Advance();            // 前进一步，返回 false 表示已到终点
robot.Reset();              // 回到路径首格
```

因此 A*、JPS、D* Lite 等只要实现 `IPathfinder`，就自动获得同一套播放、单步、
暂停、重置与状态展示。

对比模式下载体为每个算法创建一个 `Robot`：它们共享同一张 `GridMap`，
但各自持有算法实例与播放游标，所以可以独立走完自己的路径。

## 算法接入

1. 在 `../algorithms/` 新建 `NN_name/`，写实现与 `README.md`；
2. 运行 `..\tools\sync-algorithms.ps1`；
3. 重新编译；下拉框会自动出现新算法。

接口与字段说明见 `../algorithms/README.md`。

## 自检覆盖

`--selftest` 检查：

- 算法发现数量 ≥ 1；
- 每个算法的路径从 S 到 E、4 邻接、不穿墙；
- 报告代价与路径逐格求和一致；
- 声明 `Optimal` 的算法按 `Objective` 与独立 Dijkstra / BFS 对照；
- 机器人能走到终点且步数 = 路径边数，能重置；
- 对比模式：两个机器人持有独立实例，先完成者停下、另一个继续，最终各自走完；
- 最远可达格子：步数最大、并列候选按行优先、墙体隔离区不可选、单格地图、越界/空地/障碍目标、空地图、
  重复调用一致、地形代价不改变步数，距离场与独立 BFS 逐格对照；
- 周旋算法：路径从出怪口出发、经过最远格、止于入怪口；去程避让高价格；
  路线长度与代价 = 01/00 两段独立结果之和；参考点默认入怪口、墙参考点照样成功、
  参考点越界或四周全墙/断开时失败并给原因；
- 半径候选目标点：`L` 为边数、`R = floor(L * alpha)` 向下取整、`R = 0` 合法；
  整数平方圆周判定（`(3,4)/(5,0)` 命中，`(4,4)/(5,1)` 不命中）；
  区间两端相同退化为圆周、不同为圆环（含中间整数距离）、单端缺省取 `R`；
  区间为负或下界大于上界报 `InvalidRadiusRange`，不交换不夹取；
  障碍与不可达标排除；多候选全量返回、空候选仍是成功；地形代价 9 不改变 `L`；
  越界/空图/非法比例/半径溢出报错；`L`、`R`、区间与候选列表与独立 oracle 逐项对照；
- 障碍群周边最短路径：障碍群按 4 邻接墙收集（对角各自成组）、周边格去重且不含墙、
  界外方向忽略（角落群 2 格、L 形群 7 格）；受约束路线合法、含周边格；
  偏路障碍群 16 代价（高于无约束 8）、顺路障碍群 10 代价（与无约束持平）；
  高价周边格被避开、封闭房间内的障碍群报“无法同时连接”且周边格照常给出；
  同一实例两次搜索重读地图（周边格 4 → 6）、缺失/越界/空地参考点与不可通行起终点各自的失败原因；
  `Constrained` 模块跳过普通最优对照，改用逐周边格的独立 oracle（`01` 两段代价相加）；
- 最大垂直距离路径：规格算式（`Q=(5,5)` 的 12 分两例）；A 中心、B 边缘、C 起点/终点标记、
  D 无障碍、E 自然障碍、F 狭窄通道、G 多候选（高于最短路）七个场景的得分都与
  「无剪枝、枚举全部简单路径」的独立 oracle 一致；路径无重复格、得分与独立评分函数一致；
  I 起点=终点（1 格 / 0 步 / 得分 0 / 最优）；J 无合法路径（`Found=false` 且原因为「不存在合法路径」）；
  K 节点上限、L 束搜索都返回合法路线且 `IsOptimal=false`、原因分别含「节点上限」「近似」；
  M 越界标记点/缺省回退/墙标记点/墙终点；N 重复调用同分同路径、两实例各自标记点得分不同；
- 最少参考点穿越最短路径：A 无参考点与普通最短路同长；B 参考点不阻断（0 穿越、不加步）；
  C 参考点在最短路线上（宁走 6 步 0 穿越，不走 4 步 1 穿越）；D 唯一门是参考点（1 穿越）；
  E 两个参考点同时阻断（只穿 1 个）；F 同穿越数取最短；G 长路径穿 1 个优于短路径穿 2 个；
  H/I 起终点是参考点（0 穿越）；J 重复坐标只算一次；K 参考点在墙上（永不进入）；
  L 墙彻底阻断（`Found=false`、原因「不存在合法路径」）；M 起点=终点（1 格 / 0 步）；
  以上每组都与「不剪枝枚举全部简单路径」的独立 oracle 逐项比对 `(穿越数, 步数)`；
  `ValidatePathfindingResult` 能从冲突的伪造结果中报错，同实例重复调用结果一致；
- 混乱传送门：A 空设施不改变 `00`/`01` 的路径与代价；B 两门时门格变墙、路线确实传送且更短；
  C 四门时每个门的出口集合与独立推导一致、每次能到另外三个门（无固定配对）；
  D 出口全堵的门不进候选、单门不算连接；E 门费 0 时传送、门费 9 时回到纯步行；
  F 两侧出口地形不同时选便宜那一侧；G 整列墙切开的地图靠门重建通路；
  H 三门循环仍结束在简单路径；I 同一设施实例在出口被封后立刻失效（缓存戳有效）；
  J 无收益的门被忽略且代价等于纯步行；附加：门格封锁、自循环排除、门费传播、
  移除还原原价、闸门拒绝、总开关、单门禁用、`Reset`；
  每条传送路线都用 `PortalPathIsLegal` / `PortalPathCost` 独立重算；
- 单向通道：1 向右箭头边级四规则 + 直行出口（尾进→唯一首出、侧进→唯一对侧出、
  传送落点→除尾侧外全部）；2 上/下/左旋转等价；3 四条边界放置、
  探针永不越界、缺边只删边；4 首部/侧向是墙时墙规则优先；5 反向箭头走廊
  BFS/Dijkstra 都绕行且逐对合法、唯一走廊被逆箭头封死时无解；
  6 全算法扫描逐对校验（含通道内不拐弯）、7 单格走廊强制直穿、
  传送落点豁免、传送透传、`For(clone)` 重绑保持约束；
  路线用 `OneWayPathIsLegal` 独立重走；
- 指向跳板：四方向目标、距离可改、普通穿越、邻格主动使用、中途障碍、最终落点障碍、
  强制连锁、连锁落点障碍、循环、禁用跳板、越界、BFS/Dijkstra 取舍与全算法扫描、
  路径事件回放；每条路线用 `LauncherPathIsLegal` 独立审计（只查落点）；
- 单次嘲讽点：空设施保持原行为、单点多点必访、死胡同点只计一次、封锁/不可达点
  不参与约束、共同不可访问时返回无路径、与单向通道/传送门/指向跳板组合、
  动态增删与启禁用；06/07 也执行约束；路线用 `VisitsAllTaunts` 独立检查；
- 内置随机地图 25 个 seed 全部连通；
- 起终点不可被墙覆盖、全图代价可设置、墙可加可拆；
- 若 RMG 可用，读取一张 16×16 图并验证连通与可达。

## 已知边界

- 只支持 4 邻接；对角线扩展需要同时改 `GridMap` 与所有算法。
- 编辑与规划都在 UI 线程同步执行；当前 16×16 规模足够，大图需改后台规划。
- RMG 只给二值可通行图，内置地图才自带代价地斑。
- 算法模块被拷贝编译，不是运行时插件；新增算法必须重新编译。
- 查询型模块（如 `02_farthest_cell`、`04_radius_candidates`）只提供计算接口，没有 `Start → Goal` 路径，
  因此不出现在算法下拉框、也不参与对比运行；`半径候选` 预览只读查询结果，不驱动机器人；
- `距参考点最远周旋算法` 在载体里只做「选点 → 去程 → 返程」，不停滞；
  真实敌人的停滞计时需由游戏侧状态机实现。
- `障碍群周边最短路径` 只认 4 邻接的墙群，对角贴角的墙是另一群；参考点必须点在地图上的障碍，
  没有墙的地图无法满足约束（会直接失败，不会替换参考点）。
- `最大垂直距离路径` 是最大权重简单路径问题：16×16 上精确枚举不可行，默认预算内一般报
  「未证明最优」；调大 `MaxExpandedNodes` / `MaxMilliseconds` 或切到 `Beam` 会明显变慢或变成近似解，
  两者都不会改变 `IsOptimal` 的诚实性。得分模块的探索点阵在 15 万节点时会很密，属预期。
- 对比模式固定 A/B 两栏，只运行选中的两个算法；蓝/橙颜色固定不变。
- 参考点同一时刻只有一个，属于整个窗口（不属于某个机器人）；对比模式下两个算法共享它。
  `最少参考点穿越最短路径` 是例外：它持有一个参考点**集合**（同样属于整个窗口，可同时被对比的
  两个该算法实例共享），集合为空即「没有参考点」。
- 模块在单次 `Search` 内不应依赖全局可变状态；每个机器人持有一个独立实例，
  可为该机器人保留状态（例如增量重规划）。
- 嘲讽点目前由 `00` / `01` / `06` / `07` 执行；`03` / `05` 的复合目标不适合叠加
  必经点约束，选中它们时状态栏会提示「该算法不执行嘲讽点约束」。
- 传送门是**窗口级**设施（不属于某个机器人）；对比运行里两个机器人共享同一组门。
  六个路径模块与 `02` 查询模块都已接入探针，各自按自己的口径计费；A* 若要接入，
  启发函数必须先证明在低价/零价传送下仍可采纳，否则应退回 Dijkstra 基准（本版按规格未改造 A*）。
