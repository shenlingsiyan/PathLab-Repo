# 混乱传送门（Chaotic Portal）

地图拓扑扩展设施，**不是寻路算法**。它给寻路探针提供「门对门」的额外连接，
由算法自己决定用不用、走哪个出口。

```text
EntryCell → Portal A → Portal B → ExitCell
```

- 传送门数量不限（N ≥ 0），**没有固定配对**：N 个门里，每个门都能当其余 N−1 个门的入口；
- 门格**永远不可普通通行**：放置时该格被设为墙（并记住原价），删除时恢复原价；
- 敌人不会停在门格上，路径里也不会出现门格；
- 设施只发布连接与门费，**不排出口、不选出口、不碰算法的代价模型**。

代码：`PathLab/Core/PortalFacility.cs`（设施）、`PathLab/Core/IPathProbe.cs`（探针契约）。

## 1 数据与口径

```csharp
PortalFacility.Portal:
    Id              // 从 1 开始，设施内唯一、不复用
    Position        // 地图坐标
    Enabled         // 单个门的开关，默认 true
    TeleportCost    // 门费，全局统一（设施 TeleportCost 改一次，所有门同步）
```

```csharp
PortalFacility:
    IReadOnlyList<Portal> Portals
    bool Enabled                 // 总开关：false 时所有连接立刻消失，门本身保留
    int  TeleportCost            // 0..9；0 = 免费传送
    bool Add(GridMap, Cell, out string? note)
    bool RemoveAt(GridMap, Cell)
    void Reset()                 // 换新地图时忘记所有门，不回写旧地图
    void SetEnabled(int id, bool on)
    void CloseCells(GridMap)     // 地图被涂改后重新封住门格
    CellKind Kind(GridMap, Cell) // NormalWalkable / Blocked / Portal
    IReadOnlyList<Cell> NearCells(GridMap, int portalId)
    IReadOnlyList<SpecialTransition> TransitionsFrom(GridMap, Cell cell)
    bool HasUsableTransitions(GridMap)
    IPathProbe CreateProbe(GridMap)
```

`CellKind` 把「设施格」从墙和普通格子中独立出来，正好对应规格要求的
`NormalWalkable / Blocked / Portal`。地图结构本身（`GridMap`）没有为此改动。

### 入口格 / 出口格

同一个门的合法邻格集合，既当入口也当出口——**角色由这次移动决定，不由几何决定**：

1. 在地图范围内；
2. 普通可通行（`CostAt ≥ 1`）；
3. 与该门 4 方向相邻（默认四方向，不做八方向）；
4. 不是墙、不是任何门格（相邻门互相不能当对方的落脚点）。

四个方向天然不重复，无需额外去重；若门的四个邻格全不可通行，这个门**在当前地图状态下
不是有效出口**（`NearCells` 为空），它既不能被当作起点门，也不会出现在任何候选里。

### 连接规则

- 从入口格 `u` 触发：找出所有与 `u` 相邻且启用的门作为**候选入口门**；
- 对每个候选入口门 A，遍历所有与之不同、启用、且 `NearCells` 非空的 B；
- 每个 `exit ∈ NearCells(B)` 生成一条连接，但 **`exit != u`**（排除零位移自循环）；
- 全部交给算法，算法选哪个由它自己决定。

### 代价

```text
C_teleport = C_entry + C_portal + C_exit
```

- `C_entry`：走到入口格的普通移动费（进入入口格时已经付过）；
- `C_portal`：门费，**只收一次**，取自入口门的 `TeleportCost`；
- `C_exit`：落在出口格上的地形费（落地即计费，与普通移动一致）。

设施只提供 `C_portal`（`SpecialTransition.Cost`），另外两项由算法自己的计价口径加上：

| 模块 | 传送一步的代价 |
|---|---|
| `00_shortest_steps` | 1 步（忽略地形与门费） |
| `01_min_cost` | `TeleportCost + CostAt(ExitCell)` |
| `02_farthest_cell`（查询） | 1 步；反向 BFS 直接读对称的门连接 |
| `03_farthest_loiter` | 最远点由 02 用门算；两段腿各自用 01/00 的传送口径，报 `Cost` 时每次传送补一次门费 |
| `05_obstacle_cluster_route` | 两趟 Dijkstra 都接受传送，`门费 + 落点地形费`；约束环仍是普通格 |
| `06_max_perpendicular_route` | 传送算 1 步、**权重 0**（传送没有方向，不产生垂直距离），DFS / Beam 都能走 |
| `07_min_reference_traversal` | 传送算 1 步、穿越数按**落点**计（落点是参考点就 +1） |
| 未来模块 | 自己的口径，例如把门费折成距离 |

## 2 寻路探针接口

```csharp
public interface IPathProbe
{
    IEnumerable<Cell> NormalNeighbours(Cell cell);                 // 普通 4 邻接
    IEnumerable<SpecialTransition> SpecialTransitions(Cell cell); // 设施连接
}

public readonly record struct SpecialTransition(
    Cell Destination,        // 落脚的 ExitCell，必为普通可通行格
    TransitionType Type,     // Teleport
    int Cost,                // 门费（只收一次）
    int SourcePortalId,      // 入口门
    int DestinationPortalId);// 出口门
```

探针还有 `For(GridMap map)`：绑定到另一张同内容地图。`03` / `05` 会克隆地图改起终点，
它们用 `Probe.For(clone)` 而不是拿原图的探针乱用。

算法侧：

```csharp
public interface ITransitionAware
{
    IPathProbe? Probe { get; set; }   // 载体创建机器人后写入；null = 纯 4 邻接
}
```

- 两类连接**分开取**，算法在扩展节点时同时检查，再按自己的代价口径统一松弛；
- 载体 `MainForm.ApplyPortals()` 在每次建机器人时写入探针，所以单跑、对比运行都自动获得门；
- `Probe = null` 或设施里没有门时，探针行为与 `map.Neighbours` 完全一致（自检 A 对照）；
- 已接入：`00` / `01` / `03` / `05` / `06` / `07`（路径模块）与 `02`（查询模块，由 `03` 注入）。
  每个模块的传送口径见上面第 1 节的表。

### 为什么不是「门就是可走格子」

门格若只是普通可走格，任何算法都能踩上去停留、也能把门当普通通道，
「只能通过特殊连接跨越、不允许停留」这条就无法保证。因此放置门时把该格设为墙：
所有算法（无论是否理解传送门）都不可能踏上门格；理解设施的模块则通过探针额外获得连接。

### 为什么不在设施里选出口

出口的优劣取决于当前算法的目标（步数、地形代价、未来的特殊目标点）。
设施一选出口，就等于把某个算法的目标函数写进地图设施里。所以设施只把
`A → B/C/D` 的全部候选交给算法，选择留给探针的使用者。

## 3 缓存与失效

`Ensure(map)` 只在**门集合**或**每个门四邻格的地形成本**变化时重建缓存。凭据是一个 `HashCode` 戳：

```text
stamp = hash(地图宽高, 设施总开关, 门费,
            每个门: Id, 位置, Enabled, TeleportCost, 四个邻格的 CostAt)
```

- 每次查询只做 `O(P)` 的戳计算（P = 门数量），**从不扫描整张地图**；
- 戳变化 → 清空并重建：`_near`（每个门的合法邻格）、`_enteredFrom`（邻格 → 候选入口门）；
- 门增删、位移、启用/禁用、门费调整、邻格被涂成墙/空地，都会改变戳；
- 外部直接改地图（不经过设施）也能被下一次查询发现，因为戳读的是地图当前值。

## 4 边界情况与行为

| 情况 | 行为 |
|---|---|
| 没有门 | 探针退化为普通 4 邻接，结果与接入前一致 |
| 只有一个门 | `HasUsableTransitions == false`；`TransitionsFrom` 返回空 |
| 多个门 | 每个门都能当入口/出口，候选数 = 其余门的合法邻格数之和 |
| 总开关关闭 | 所有连接为空，门本身仍在地图上显示 |
| 某个门被禁用 | 它既不能当入口也不能当出口 |
| 门四周全不可通行 | `NearCells` 为空，该门不是有效出口 |
| 门四周部分被堵 | 只保留仍可通行的邻格 |
| 两个门相邻 | 各自邻格互相排除，不会出现「A→B 出口就在 A 的邻格」这种零位移结果 |
| 门之间很远 | 只是连接距离长，规则不变 |
| 门放在墙上 | 允许；移除后恢复为墙（`RestoreCost`） |
| 门放后被涂成空地 | `CloseCells` 会重新封回墙，避免门格变成可走格 |
| 动态删除 | `RemoveAt` 恢复原价并让缓存失效 |
| 启用状态变化 | 戳变化，下一次查询立即反映 |
| 循环连接 | 连接是全对多的，出现环是正常的；算法各自保证不重复访问 |
| 门费为 0 | 免费传送；`01` 只会付出口格地形费 |
| 起点/终点旁有门 | 起点、终点本身就是合法入口/出口格，可以立刻传送 |
| 出口全被其他规则排除 | 该门不进候选 |

起点与终点本身**不能放置门**（`Add` 返回 false 并给出原因），否则门格与固定闸门语义冲突。

## 5 独立验证与测试（`--selftest`）

自检不调用设施内部的候选生成，而是**重算一遍**：

```text
PortalPathIsLegal(map, facility, path)   // 每步要么 4 邻接，要么「离开一个启用门的邻格、
                                        // 落到另一个启用门的邻格」；不越界、不穿墙、不踩门、不重复
PortalPathCost(map, facility, path)      // 逐格重算地形费 + 每次传送补一次门费
ExpectedPortalExits(map, facility, u)    // 从入口格独立推导应得的出口集合
```

| 用例 | 构造 | 断言 |
|---|---|---|
| A 没有门 | 5×5 开放图，空设施 | `00` / `01` 的路径与代价和未接探针时完全一致 |
| B 两个门 | 5×5，门在 `(1,1)`、`(3,3)`，门费 0 | 门格变墙、`Kind == Portal`；路线合法且确实传送；步数少于纯步行 |
| C 四个门 | 7×7，四角门 | 每个门的出口集合 = 独立推导的集合；每次都能到达另外 3 个门，无固定配对 |
| D 出口全堵 | 5×5，一门四周全墙 | 该门邻格为空；只剩一个可用门时 `HasUsableTransitions == false`；它不出现在候选里 |
| E 门费决定取舍 | 门费 0 / 门费 9 两张同构图 | 免费时 `01` 传送且更便宜；昂贵时 `01` 不传送、代价等于纯步行 |
| F 地形决定出口 | 一门入口，两门出口，其中一侧地形全 9 | `01` 落在便宜那侧的出口；代价与独立重算一致 |
| G 门补通路 | 7×5，整列墙把地图切成两半，两侧各一门 | 不接探针不可达；接探针后找到合法路线 |
| H 循环连接 | 5×5，3 个门互相可达 | 搜索正常结束，路径不重复格子 |
| I 动态失效 | 先让出口可用并确认被使用，再把该门四邻全封 | 同一个设施实例立刻看到「无出口」；下一次搜索不再用旧出口 |
| J 没有收益 | 门费 9，门放在绕远位置 | `01` 忽略传送，代价等于纯步行 |
| 附加规则 | 门的单元格、自循环、门费传播、移除恢复、闸门拒绝、总开关、单门禁用、`Reset`、单门无伙伴 | 各自断言（见 `SelfTest.cs` 中 `portal rules:` 段） |
| 探针重绑 | `Probe.For(clone)` | 克隆图看到与原图相同的连接（`03` / `05` 的两段腿依赖它） |
| 02 最远点 | 7×5，一个只有门能进的口袋 | 不接探针该格不可达；接探针后它成为最远格，距离 = 纯步行最远 + 1 |
| 03 周旋 | 7×5，两格口袋夹在两道门之间 | 路线转向 02 给出的最远格，且确实含该格；出返两段都传送；代价可独立重算 |
| 05 障碍群 | 9×5，整列墙切开，障碍群在另一半 | 不接探针报「无法同时连接」；接探针后 `ViaCell` 落在约束环上，路线跨墙传送 |
| 06 垂直距离 | 5×3，起点被两门封住 | 纯步行无解；接探针必须跳出去，得分可独立重算，路径不重复格子 |
| 07 参考点 | 5×5 两门，一个出口格是参考点 | 路线宁可换落点也不踩参考点；验证器接受传送步；落点全是参考点时穿越数 ≥ 1 |

## 6 界面

编辑行新增两个控件：`传送门` 模式按钮、`传送代价` 数字框（0..9，默认 2）。

- **同一时刻只有一个工具生效**：`障碍` / `代价` / `擦除` / `传送门` / `选参考点` 互斥。
  进入 `选参考点` 后所有绘制按钮熄灭、画布左右键都只做拾取（右键不会放门）；
  点任一绘制按钮会立刻取消拾取并恢复高亮；
- 选中 `传送门` 模式后：**左键放置、右键移除**，拖动也生效（同一格只触发一次）；
- 提示行变为 `左键放传送门 · 右键移除 · 门格不可通行`；
- 门格画 `P` **方形**角标；`R`（参考点）与 `F`（转折格）仍是圆形，形状即类别；
- 路径遇到传送会**断开**：每段连续 4 邻接单独画线、单格画点，不会出现横跨地图的假斜线；
- 状态栏在有传送时追加 `· 传送 N 次`：
  `最短路程 (BFS) · 19 步 · 代价 19 · 传送 1 次 · 扩展 190 · 1.0 ms · RMG · seed 20261025`；
- 换新地图会清空所有门；改门费、增删门、涂改地图都会立即重算。

## 7 约束

- 不改 `GridMap` 的数据结构：门格靠「设为墙 + 记住原价」实现，移除时还原；
- 不改随机地图生成器：生成的图里天然没有门；
- 不改既有算法的核心：六个路径模块各只多了一个可选探针和一条「传送松弛」分支，
  未接探针时行为不变（自检 A 与既有的 07/06/05/03 用例全部保持通过）；
- 六个路径模块与 `02` 查询模块都已接入；没有任何模块被要求为传送门改写目标函数；
- `03` 的两段独立求解意味着：口袋这类「进得去、只能原路出来」的地形里，
  复合路线可能复用去程格子（先尝试避开，避不开才回退）。它不声称最优，界面照常播放；
- 不在设施里写死出口选择、不固定配对、不排序「哪个出口离终点更近」；
- 不允许传送到墙、地图外、其他门格；不允许停留在门格上。

## 8 极简

一个设施类、一个探针接口、一个 `SpecialTransition` 结构体、一个 `CellKind` 枚举；
缓存只有两张字典 + 一个 `HashCode` 戳；界面只加了一个模式按钮和一个数字框。
没有新的地图类型、没有运行期插件、没有第二套邻接规则。
