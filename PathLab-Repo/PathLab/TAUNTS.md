# 单次嘲讽点（Single-use Taunt Point）

地图设施，**不是移动事件、不是方向控制、不是敌人 AI**。它给一个仍然可通行的
格子打上「必经」标记：下一次寻路必须经过所有**能够纳入合法起点→终点路线**的
嘲讽点，每个只算一次；全部访问完之后还必须能继续到达终点。

```text
S ──→ [T] ──→ E        一次寻路经过 T 一次即可
```

- 嘲讽点**不阻挡通行**、**不改变地形代价**、**不修改普通邻接**；
- 它只向寻路系统提供一个「必须访问」的约束；
- 「单次」是一轮寻路的语义：该点不会在地图上消失，也不会被某个敌人永久消耗。

代码：`PathLab/Core/TauntPointFacility.cs`（设施数据）、
`PathLab/Core/TauntPlan.cs`（有效集合 + 位掩码 + 状态图可达性）。

```

TauntPointFacility:

```

放置只接受地图内、非起点/终点、空格子。设施**不涂改地图**：格子价格、墙规则、
起点/终点、普通四邻接全部保持原样。一个被涂成墙的嘲讽点是合法设施，但它永远
不在有效集合里（见第 3 节）。

## 2 有效集合 T'

设 `S` 起点、`G` 终点、`T` 当前所有启用的嘲讽点：

```text
T' = { t ∈ T | 存在一条合法的 S→G 路线经过 t }
```

`TauntPlan.Build(map, probe, points)` 负责计算 `T'`，只把有效点分配访问位（
行优先排序，位号从 0 开始）。

### 2.1 判定方法

合法路线必须遵循**完整移动规则**：普通移动、单向通道的直线穿越、传送门连接、
指向跳板连锁。因此判定直接在 `(cell, entry)` 搜索状态图上做：

1. 枚举全图可行状态：普通格一个状态；单向通道格按进入方向各一个状态；
2. 每个状态的合法后继 = `probe.ExitsAfter(entry, cell)`（普通出口）+
   `probe.SpecialTransitions(cell)`（设施跳转，步行进入通道后不给）；
3. 从 `(S, S)` 正向 BFS，得到「从起点可达的状态」；
4. 反向图从所有 `(G, *)` 状态反向 BFS，得到「还能抵达终点的状态」；
5. 某嘲讽点有效 ⇔ 它所在格子存在一个状态同时被正向与反向可达。

这样同时满足任务书的三个条件：格子本身可通行、从起点可达、从该点仍可抵达终点。

### 2.2 常见排除情况

| 情况 | 结果 |
|---|---|
| 点在地图外 | 放置时直接拒绝 |
| 点在墙上 / 四周被墙封死 | 不进入 `T'` |
| 从起点不可达 | 不进入 `T'` |
| 可达但只能进不能出（死胡同） | 不进入 `T'` |
| 同一格有多个点 | 只能放一个；同格只有一个点，天然共用一位 |
| 点在传送门格上 | 门格是墙，不是有效点 |

### 2.3 共同可访问性

`T'` 只保证**每个点单独**能出现在某条 S→G 路线上。寻路本身用
`(Position, VisitedMask)` 扩展状态同时尝试所有点：

- 存在一条路线同时经过 `T'` 全部点 → 返回该路线；
- 不存在 → 返回 `Found == false`，`Note` 写
  `无法同时经过全部 N 个嘲讽点`，`TauntRequiredCount` 仍报告 N。

**不会**因为「A 可达、B 可达」就假装任务完成，也**不会**为了成功而擅自丢掉
某个有效点。等价于在一个有向图里做带必经点约束的最短路。

## 3 扩展状态与终点判定

```text
State = (Position, Entry, VisitedTauntMask)
```

- `Entry`：进入格（仅单向通道格有意义，其余格固定为自身），沿用既有状态口径；
- `VisitedTauntMask`：有效点的访问位；进入某格时若该格是有效点，置位；
  重复进入同一格不会重复计数；
- 终点条件：`Position == G && VisitedTauntMask == FullMask()`。

已经访问过的点不会再次施加要求，也不会阻止再次经过（测试 4 的死胡同回返
就是靠这一点）。位掩码只在有效点数量较小的时候使用；当前地图规模与设施数量
下 `2^N` 完全可接受，若未来单图点数量很大，再考虑分组/剪枝，而不是牺牲正确性。

### 3.1 状态转移

普通移动与特殊移动走同一条路径：

```text
Next = (NextCell, NextEntry, Mask | BitOf(NextCell))
```

- 传送门落点、跳板连锁最终落点、普通步行落点，只要是有效嘲讽点就置位；
- 跳板连锁**中间经过**的格子不是路径节点，不置位（只看最终落点，符合任务书
  对实际经过格子的定义）；
- 一次性跳板移动仍然只算它原本的代价/步数，嘲讽点不额外收费。

## 4 寻路接入

新增可选接口：

```csharp
public interface ITauntAware
{
    TauntPlan? Taunt { get; set; }   // null 或空计划 = 原行为
}
```

载体每次规划时重建计划并写入模块：

```csharp
_activeTaunt = TauntPlan.Build(_map, _activeProbe, _taunts.EnabledPoints());
if (robot.Algorithm is ITauntAware tauntAware) tauntAware.Taunt = _activeTaunt;
```

### 4.1 已接入模块

| 模块 | 处理方式 |
|---|---|
| `00_shortest_steps` | 状态加 mask；终点必须全访问；仍然按步数最优 |
| `01_min_cost` | 状态加 mask；终点必须全访问；仍然按进入代价最优 |
| `07_min_reference_traversal` | 状态加 mask；字典序目标不变；有约束时允许路径重复格 |
| `06_max_perpendicular_route` | 种子路径带约束；简单路径终点必须包含全部有效点；目标仍是最大化得分 |

`03_farthest_loiter` 与 `05_obstacle_cluster_route` 是复合目标（分别由「最远点
去/返两段」和「障碍群周边双 Dijkstra 汇合」定义），强制点约束会改变它们的路线
定义，因此**没有**接入；选中它们且地图上有有效点时，状态栏显示
`· 该算法不执行嘲讽点约束`，不会静默给出违反约束的路线。

`02` / `04` 是查询模块，没有完整 S→G 路径，不参与该约束。

### 4.2 成本目标

嘲讽点只增加约束，不改目标函数：

- BFS 仍然最少步数（在满足约束的路线中）；
- Dijkstra 仍然最小累计进入代价；
- 07 仍然是「先穿越数、再步数」的字典序；
- 06 仍然最大化垂直距离得分，只是终点必须包含全部有效点。

### 4.3 与其它设施的兼容

| 组合 | 行为 |
|---|---|
| 单向通道 | 有效集合与搜索都走 `ExitsAfter`，不会为访问嘲讽点而逆向穿越 |
| 传送门 | 落点是嘲讽点时正常置位；门格永远不是路径节点 |
| 指向跳板 | 连锁最终落点是嘲讽点时置位；中间落点不置位；跳跃代价不变 |
| 三者同时存在 | 组合探针（portal → one-way → launcher）同时参与有效集合与搜索 |

## 5 动态变化

`TauntPlan` 是**每次规划时新建**的快照，设施本身不缓存：

- 增删嘲讽点、启用/禁用、改障碍、改单向/传送/跳板 → 下一次 `PlanAll` 重建
  `T'` 并重新搜索；
- 载体在每次 `PlanAll` 之前重建计划，编辑地图后不会复用旧约束；
- 没有寻路缓存，因此不存在过期结果。

## 6 性能

- 有效集合：状态图有 `O(V)` 个节点（只有单向通道格会按进入方向分裂），
  正向 + 反向两次 BFS，不做整图重复扫描；
- 搜索：`O(V · 2^N)` 个状态。`N` 为有效点数；当前单图通常只有个位数；
- 状态以 `(cell, entry, mask)` 为键去重，完全相同的状态不会重复扩展；
- 每次状态转移只做一次字典查位，不扫描全图找嘲讽点。

## 7 界面

- 编辑行新增 `嘲讽点` 按钮；左键放置、右键移除，与其它设施同一套手势，
  **同一时刻只有一个工具生效**；
- 画布把嘲讽点画成**红色小正方形**（格子中心），与端口 `P`、单向橙箭头、
  跳板绿箭头明确区分；
- 状态栏在有有效点时追加 `· 嘲讽点 x/y`；不支持该约束的算法追加提示；
- 换新地图会清空所有嘲讽点。

## 8 测试（`--selftest`，taunt 系列）

| 组 | 覆盖 |
|---|---|
| taunt 1 | 没有嘲讽点：BFS / Dijkstra 的路径与代价与原行为完全一致 |
| taunt 2 | 单个有效点必被经过；被墙封死的点不进入约束 |
| taunt 3 | 三个有效点全部出现在同一条路线（顺序不限）|
| taunt 4 | 死胡同点只计一次；路径可以二次经过相邻格而不重复要求 |
| taunt 5 | 封锁点被跳过，同图的可达点仍然强制 |
| taunt 6 | 从起点可达但无法再抵达终点的点不进入有效集合 |
| taunt 7 | 两点各自可达但无法共同访问：搜索返回无合法路径与明确原因 |
| taunt 8 | 与单向通道、传送门、指向跳板组合；特殊移动落点正确置位且规则不被破坏 |
| taunt 9 | 新增 / 删除 / 启用 / 禁用后下一次寻路立即反映；06 / 07 同样执行约束 |
| taunt rules | 越界、闸门、重复放置拒绝；移除与 `Reset` |

辅助断言：`VisitsAllTaunts(path, plan)` 检查有效点是否都在路线里。

## 9 约束兑现

- 独立设施，不阻挡通行，不改地形代价与普通邻接；
- 不直接控制敌人移动，只提供路径约束；
- 只强制有效点，每个只要求一次；
- 所有有效点必须由同一条合法路线访问，之后还要抵达终点；
- 不可达 / 封锁 / 无法纳入 S→G 的点不参与约束；
- 保留原有成本优化目标（步数 / 代价 / 字典序 / 得分）；
- 兼容单向通道、传送门、指向跳板；
- 不改地图随机生成，不改其它设施的既有行为；
- 无耐久、冷却、次数消耗、攻击效果。
