# 单向通道（One-Way Passage）

地图规则设施，**不是寻路算法**。它占据一个**仍然可通行**的格子，禁止
「首部侧进入」与「向尾部侧离开」两条边；并且**穿越必须直线**——步行进入
通道后唯一出口是直行对侧，通道内不允许拐弯。

```text
        ↑ 首部
        |
尾部 → [C] → 首部      （以向右的箭头为例）
        |
        ↓
```

- 通道格**不涂改地图**：地形代价保留，任何算法都可以踩上去，只是进出方向受限；
- **首尾轴**：只许尾进首出的直线穿越；侧向边在候选池里仍然双向存在，
  但步行进入通道后只能直行离开（侧进侧出保留，侧进尾出/尾进侧出禁止）；
- **传送落点豁免**：传送没有几何进入方向，落点是通道格时允许除尾侧外的
  任意出口，通道仍保持单向身份；
- 步行进入通道后不能再传送离开（必须直行走完）；
- 设施不触碰任何算法的目标函数、代价模型与优先级规则。

代码：`PathLab/Core/OneWayFacility.cs`（设施 + 探针过滤器）。

## 1 数据与核心规则

```csharp
public enum Direction { Up, Down, Left, Right }

public readonly record struct OneWayPassage(Cell Position, Direction Direction);
```

`Direction` 是箭头指向，即**从尾部指向首部**的方向（Y 轴向下，`Up = (0,-1)`）。

规则分两层。

**边级禁行**（上下文无关，对任何 A→B 的 4 邻接移动）：

```text
A == C+D && B == C      （从首部侧进入，禁止）
A == C && B == C-D      （向尾部侧离开，禁止）
```

**直线穿越**（上下文相关，由 `IPathProbe.ExitsAfter(entry, cell)` 给出）：

```text
从邻格 P 步行进入通道 C：唯一出口 = 2C - P（尾进 → 首出，侧进 → 对侧出）
出口越界或是墙，则该进入状态本身是死路。
传送落到通道 C（无几何进入方向）：出口 = 除尾侧 C-D 外的全部邻格。
```

以向右箭头为例：左侧进 → 右侧出 ✓、上侧进 → 下侧出 ✓（直穿保留）；
左进后想往上拐 ✗、右侧进 ✗、左侧出 ✗。其余三个方向按相同规则旋转。

> **与任务书 4.3 节的差异说明**：任务书 4.3 写作禁止 `A == C-D && B == C`
> （尾部侧进入），这与任务书自己的规则 1（「只能从尾部进入」）和 4.2 示例
> （「从左侧进入：允许」）矛盾。实现以 4.2 示例与验收标准为准：
> 只禁「首部侧进入」与「尾部侧离开」。
> **后续修订**：应用户要求，穿越语义从「仅限首尾轴两条边」收紧为
> 「**穿越必须直线，保留侧向直穿**」——搜索状态在通道格上按进入方向分裂。

## 2 探针接入

单向通道是**对边的约束**，不是新连接，所以它不走 `SpecialTransitions`，
而是过滤普通邻接，并按进入方向收紧出口：

```csharp
public bool BlocksMove(Cell from, Cell to);          // 边级禁行：离开通道 / 进入通道
public IPathProbe ApplyTo(IPathProbe inner);         // 包装任意探针，过滤普通邻接
public static IPathProbe Plain(GridMap map);         // 无设施的普通探针（墙过滤 + 4 邻接）
```

`IPathProbe` 新增两个默认接口成员（老探针零改动，缺省退化为 `NormalNeighbours`）：

```csharp
bool IsOneWay(Cell cell);                            // 该格是否通道格
IEnumerable<Cell> ExitsAfter(Cell entry, Cell cell); // 给定进入方向的单步出口
```

- `FilteredProbe.NormalNeighbours(cell)` = 内层探针的普通邻接 **减去** 违箭头的边
  （上下文无关候选池）；
- `FilteredProbe.ExitsAfter(entry, cell)`：非通道格 = 同上候选池；通道格按
  直线规则收紧（步行进入 → 唯一直行出口；无几何进入 → 除尾侧外全部）；
  候选池由内层探针提供，墙与代价规则照常生效；
- `SpecialTransitions` **原样透传**：传送不是几何边，不受箭头约束；
  但落点之后的每一步普通移动照常受限，且步行进入通道后不再提供传送；
- `For(map)` 逐层重绑，`03` / `05` 的克隆图拿到的过滤器不变。

**搜索状态分裂**：因为出口依赖进入方向，BFS / Dijkstra 类模块把状态从
「格子」扩为「(格子, 进入格)」二元组，只在通道格上分裂，其余格子退化为
单状态；传送落点与搜索起点用「进入格 = 自身」表示无几何进入。路径式搜索
（06）天然知道前驱，直接读 `ExitsAfter(prev, current)`，无需状态分裂。
步数/代价口径不变：穿通道仍是 2 步（进 + 出）。

载体侧（`MainForm.ApplyFacilities`）：

```csharp
aware.Probe = _oneWay.ApplyTo(_portals.CreateProbe(_map));
```

所有实现 `ITransitionAware` 的模块（`00` / `01` / `02` / `03` / `05` / `06` / `07`）
拿到的都是同一个组合探针，**没有任何算法内部出现单向通道判断**；
不认识设施的算法设置 `Probe = null` 时保持原行为。

## 3 边界情况

| 情况 | 行为 |
|---|---|
| 通道紧贴任意边界 | 允许放置；缺失的首部/尾部边自然不存在，越界永远不可通行 |
| 首部/尾部紧贴障碍 | 障碍照常不可通行；箭头约束只作用于实际存在的边 |
| 两侧都被障碍堵死 | 允许；只剩首尾轴上的单向通行 |
| 周围只有一两个合法邻格 | 允许；不因缺邻居而删除通道 |
| 移动两端都是通道格 | 两条边分别独立判 |
| 起点与终点 | 不能放置通道（与传送门一致）|
| 同格重复放置 | 拒绝，提示「该格已有单向通道」|
| 通道格被涂成墙 | 墙优先：格子不可通行，通道仍在，拆墙后约束恢复 |
| 通道 + 传送门 | 传送跳不受箭头约束，落地后的步行受限 |
| 换新地图 | `Reset()` 清空所有通道（通道不写地图，无需还原）|

## 4 界面

- 编辑行新增 `单向` 按钮 + `箭头` 下拉框（↑ 上 / ↓ 下 / ← 左 / → 右，默认 → 右）；
- 左键放置、右键移除，与传送门同套手势；**同一时刻只有一个工具生效**（含拾取互斥）；
- 画布把通道画成**橙色箭头**（杆 + 箭头尖，指向首部），与 `R`/`F` 圆形角标、
  `P` 方形角标明确区分。

## 5 测试（`--selftest`，oneway 系列）

| 组 | 覆盖 |
|---|---|
| oneway 1 | 向右箭头：边级（尾进 ✓、首出 ✓、首进 ✗、尾出 ✗、两侧候选池双向）+ 直行（尾进→唯一首出、侧进→唯一对侧出、传送落点→除尾侧外全部）|
| oneway 2 | 上/下/左三个方向的旋转等价性（边级 4 条 + 直行 2 条）|
| oneway 3 | 四条边界的边界放置、探针永不越界、缺失边只删边不删设施 |
| oneway 4 | 首部/侧向是墙时：墙规则优先，开口方向仍按箭头规则 |
| oneway 5 | 反向箭头走廊：无设施 4 步直行 → 有设施 BFS/Dijkstra 都绕行且逐对合法；唯一走廊被逆向箭头封死时无解 |
| oneway 6 | 全算法扫描：`AlgorithmHost` 里每个模块的路径逐对校验（界内、非墙、4 邻接、不违箭头、通道内不拐弯）|
| oneway 7 | 单格走廊强制直穿：唯一合法路线必须直线穿过箭头，步行进入后无侧向出口（BFS + Dijkstra）|
| oneway 落点 | 传送可落在通道格：落点保留除尾侧外的全部出口，单向身份不丢 |
| oneway+portal | 传送数量透传不变；落点之后的步行仍受箭头约束 |
| oneway probe | `For(clone)` 重绑后箭头约束不变 |

路径校验 helper：`SelfTest.OneWayPathIsLegal(map, facility, path)`——
对每一对连续坐标检查界内、非墙、4 邻接、`BlocksMove` 为假，并对路径中
每个通道格做**三元组直行校验**（path[i-1]→path[i]→path[i+1]：进入格与
出口必须关于通道格中心对称）。

## 6 约束兑现

- 不改地图随机生成机制（RMG / 内置生成器零改动）；
- 不改普通障碍定义（墙仍是代价 0）；
- 不改任何算法的核心目标、代价计算与优先级（规则全部在探针层）；
- 不为单向通道复制寻路算法；
- 无冷却、次数、耐久等额外机制；设施只含 `Position + Direction`，可继续扩展。
